1. The Core Problem: Why Not NAS/SAN for Web Media?

Enterprise networks commonly use SAN (Storage Area Networks) for raw OS blocks and NAS (Network Attached Storage) for shared folder hierarchies. While NAS is suitable for internal office drives, using it for web clients introduces severe bottlenecks:

  • Compute Choke Points: To serve a file from a NAS mount, your web server must read the file and stream every byte over its own network interface. 10,000 downloads will saturate server bandwidth.
  • Payload Limits: Serverless hosts (such as Vercel or AWS Lambda) strictly limit request body sizes (e.g., 4.5 MB). Direct client uploads to the application server fail for large files.
  • The S3 Advantage: S3 is an HTTP-native object store. Using Presigned URLs, web clients stream downloads and uploads directly to/from S3 over standard REST endpoints—completely bypassing web servers.

2. Student Setup Instructions

Step A: Create AWS IAM Programmatic Credentials

  1. Log into the AWS Management Console.
  2. Navigate to IAM > Users > Create user (e.g., s3-lab-user).
  3. Under permissions, select Attach policies directly and attach AmazonS3FullAccess.
  4. Go to the user's Security credentials tab > Create access key > Select Local code / CLI.
  5. Save your Access Key ID and Secret Access Key.

Step B: Run Setup & Seed Private Asset

  1. Open the Lab Portal (linked above) and switch to the Lab Code Repository tab.
  2. Copy setup_storage.py and generate_links.py to your local machine.
  3. Set your AWS credentials in your environment: 
    export AWS_ACCESS_KEY_ID="your_key"
export AWS_SECRET_ACCESS_KEY="your_secret"
export AWS_DEFAULT_REGION="us-east-1"
export VAULT_BUCKET_NAME="vault-<student-id>-lab"
  4. Install dependencies and provision the bucket: 
    pip install boto3
python setup_storage.py
  5. Run python generate_links.py to upload the test asset and generate temporary presigned URLs.

Step C: Test Direct Transfers in the Lab Portal

  1. Go back to the Live URL Testing Studio tab on the Vercel Lab Portal.
  2. Paste the Presigned GET URL into Test 1 and click Stream Asset from S3. Verify the image renders directly from AWS S3 without passing through Vercel.
  3. Paste the Presigned PUT URL into Test 2, select a local PNG image, and click Stream Upload Directly to S3. Observe the direct HTTP PUT payload delivery.
  4. Wait 60 seconds (after the GET link's TTL expires) and re-test to verify S3 returns a 403 Forbidden response.
