Storage Architecture Comparison

Understanding when to select S3 (Object) versus traditional NAS (File) or SAN (Block).

Attribute SAN (Storage Area Network) NAS (Network Attached Storage) AWS S3 (Object Store)
Storage Unit Raw Disk Blocks Hierarchical Files & Directories Objects (Flat Key-Value + Metadata)
Access Protocol Fibre Channel, iSCSI NFS, SMB / CIFS HTTP/HTTPS REST APIs
Client Interface Direct OS kernel attachment Mounted network filesystem Any Web Browser, Mobile App, or CLI
Web Scalability Limited to host VM Severely throttled by app server NIC Virtually infinite; edge distributed
Cost Factor High (Dedicated Fibre/SAN arrays) Medium-High (Compute + Provisioned IOPS) Low ($0.023/GB, Pay-as-you-go)
Client Offloading None None (Web server must read and proxy) Native: Presigned URLs delegate transfers

Key Architectural Takeaway

In high-scale web systems, using NAS requires every byte to be read by the backend server and forwarded to the user, creating a CPU and bandwidth choke point. With S3, your backend merely acts as an authorization token generator (creating SigV4 links), while 100% of the heavy data transfer happens directly between the browser and AWS storage infrastructure.
