1. The Core Problem: Why Not NAS/SAN for Web Media?

Enterprise networks commonly use SAN (Storage Area Networks) for raw OS blocks and NAS (Network Attached Storage) for shared folder hierarchies. While NAS is suitable for internal office drives, using it for web clients introduces severe bottlenecks:

  • Compute Proxy Bottlenecks: To serve a file from a NAS mount, your web server must open the file and stream every byte over its own NIC. 10,000 downloads will saturate server bandwidth.
  • Payload Limits: Serverless hosts (such as Vercel or AWS Lambda) strictly limit request body sizes (e.g., 4.5 MB). Uploading directly through the application server fails for larger media.
  • The S3 Advantage: S3 is an HTTP-native object store. Using Presigned URLs, web clients stream downloads and uploads directly to/from S3 over standard REST endpoints—completely bypassing web servers.

2. Student Setup Instructions

Step A: Create AWS IAM Programmatic Credentials

  1. Log into the AWS Management Console.
  2. Navigate to IAM > Users > Create user (e.g., s3-lab-user).
  3. Under permissions, select Attach policies directly and attach AmazonS3FullAccess (or scope to your lab bucket).
  4. Go to the user's Security credentials tab > Create access key > Select Local code / CLI.
  5. Save your Access Key ID and Secret Access Key securely.

Step B: Create a Private S3 Bucket

  1. Navigate to Amazon S3 > Create bucket.
  2. Name your bucket uniquely (e.g., vault-<student-id>-lab) and choose your preferred AWS Region.
  3. Leave Block Public Access set to ON (Checked). (This proves the bucket remains 100% private to the public).

Step C: Configure Bucket CORS (Required for Web Browsers)

Because you will be streaming data directly between your browser (visiting the Vercel app) and AWS S3, S3 must allow Cross-Origin Resource Sharing.

  1. Open your new bucket > click the Permissions tab.
  2. Scroll to Cross-origin resource sharing (CORS) > click Edit.
  3. Paste the following JSON rule and click Save changes:
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedOrigins": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]

Step D: Run the Scripts from the Lab Portal

  1. Open the Lab Portal (linked at the top of this page) and switch to the Code Repository tab.
  2. Copy generate_links.py to your local machine.
  3. Install Boto3: pip install boto3.
  4. Set your credentials via terminal or .env: 
    export AWS_ACCESS_KEY_ID="your-key"
export AWS_SECRET_ACCESS_KEY="your-secret"
export AWS_DEFAULT_REGION="your-region"
export VAULT_BUCKET_NAME="vault-<student-id>-lab"
  5. Execute python generate_links.py.
  6. Copy the generated Presigned GET URL and paste it into the Live Inspector tool on the Vercel Lab Portal.
